# 通用中文六爻 Skill 设计规格

**日期：** 2026-08-29  
**目标目录：** `C:\Project folder\liuyao-skill`

## 目标

创建一个可独立上传 GitHub、可被 Codex 自动发现的中文六爻解读 Skill。它接收文字排盘或排盘截图中的结构化信息，按照传统六爻的理法与象法分层分析，并输出可复核、标注依据和不确定性的解读。Skill 面向关系、寻物、工作、财务等一般占问，不把卦象包装成确定事实或替代现实世界的专业判断。

## 已确认范围

- 排盘字段识别：起卦时间、干支、旬空、本卦、变卦、世应、六亲、六神、地支、动爻。
- 理法判断：问事分类、用神/原神/忌神、月建日辰、旺衰、生克、冲合、刑害、旬空、伏神、动变、进退和应期。
- 象法判断：六神、六亲、爻位、卦名/上下卦和组合之象；象法只能在理法基础上收敛结论。
- 结果表达：先给结论，再给证据链、时间窗口、反证和现实建议；多用神或数据不足时明确说明。
- 资料检索：按专题从三本用户提供的 OCR 资料中提炼的参考索引中查找，不把整本 OCR 原文打包进 Skill。
- 验证示例：包含用户提供的“前男友近状”截图盘面，验证空亡、动变、辰酉合、世应和关系问题的谨慎表达。

## 不在范围内

- 不实现新的排盘算法、历法换算器或截图 OCR 程序。
- 不自动访问社交平台、联系人、定位、医疗、金融或法律系统来“验证”卦象。
- 不将单一神煞、卦名、空亡或某个动爻直接等同于现实结果。
- 不发布三本 OCR 文件的完整复制品；原始文件留在用户本地资料目录中。

## 方案与取舍

采用分层 Skill 包：主入口保持短小，模式细节放在按需读取的 `references/`，示例单独放在 `examples/`。

- 相比单文件方案，分层结构减少每次调用的上下文负担，并允许后续修订单个主题。
- 相比加入排盘脚本的完整工具方案，当前结构不引入历法和 OCR 误差，也不会让模型把“计算”误认为“判断”。
- 自动调用保持开启；描述只写触发条件，不在 frontmatter 中复述完整工作流。

`SKILL.md` 负责触发边界、分析顺序、输出合同和参考资料路由。四份主题参考文档分别负责通用流程、取用神与旺衰、关系与应期、象法；`source-index.md` 负责记录三本资料的来源、可检索专题和 OCR 使用警告。示例文件只展示结构化盘面如何推理，不宣称示例结论是事实。

## 输入与数据流

```text
用户问题/排盘文字/截图
        ↓
字段转录与一致性核对
        ↓
确定问事类型、世应和候选用神
        ↓
理法：日月旺衰 → 生克冲合刑空 → 动变/伏神 → 事件走向
        ↓
象法：六神/六亲/爻位/卦象组合，验证或补充理法
        ↓
应期候选与不确定性
        ↓
结论、依据、限制、可执行建议
```

截图信息不清时先列出“已确认字段”和“待确认字段”，不得静默猜测。文本排盘中若本卦、变卦、动爻或世应互相矛盾，先指出矛盾并以用户确认的数据为准。

## 输出合同

每次解读使用以下顺序，篇幅随问题复杂度调整：

1. **结论**：回答用户真正问的事情，使用“较可能/倾向/暂难确认”等概率性措辞。
2. **盘面核对**：列出影响结论的关键字段和数据质量问题。
3. **理法依据**：说明用神、世应、旺衰、动变及主要关系如何共同指向结论。
4. **象法补充**：只写与问题相关的组合象，并说明它是辅助证据。
5. **时间与条件**：给出应期候选及触发条件；没有充分依据时不硬给日期。
6. **现实建议与边界**：给出低风险、可验证的下一步；健康、财务、法律和人身安全问题明确建议现实专业渠道。

## 质量与测试

Skill 包使用 `skill-creator` 的初始化器和 `quick_validate.py` 检查 frontmatter、命名和残留脚手架。行为验证至少覆盖：

- 能从用户示例中抽取并复述关键盘面字段；
- 不把官鬼酉金旬空、化妻财等单一线索升级为“对方确定有新欢”；
- 能区分理法证据与象法补充，并承认官鬼两现/取用不唯一等不确定性；
- 在用户未提供完整盘面时先请求或列出缺失字段；
- 对健康、财务、法律和安全问题保留现实决策边界。

验证记录放在 `examples/relationship-reading.md`，并通过独立的文本检查和 Skill 校验命令复核。每个阶段完成后提交 Git，最终仓库不包含用户原始 OCR 文件和截图。
