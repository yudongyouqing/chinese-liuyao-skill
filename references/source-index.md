# OCR 来源与检索索引

本仓库包含三份中文六爻 OCR 原始文本，位于 `../sources/`。本索引把问题主题映射到对应文件和检索词，帮助 Agent 在精炼参考不足、术语存在歧义或用户要求原文依据时按需回查。

`references/` 保存适合默认读取的精炼规则；`sources/` 保存用于扩展和核对的原始 OCR。完整解读不默认一次性加载三本全文，应先根据占问主题选择相关文件和局部上下文。

## Agent 检索流程

1. 先读取 `method-and-output.md`，完成占问分类、盘面字段核对和候选用神判断。
2. 根据问题只选择一份或少数几份相关资料。例如，先在“六爻理法进阶”中查月建、日辰和合冲，再在象法资料中查六神或爻位。
3. 使用本索引中的关键词在对应 `sources/` 文件中检索，不默认把三本全文同时放入上下文。
4. 读取命中位置附近的必要上下文，并把文件名、关键词和相关原意作为资料依据记录下来。
5. 将 OCR 资料与已核对的盘面事实、采用的流派口径和自身推断分开表达；资料内容不能替代盘面校验。

## 快速检索

在仓库根目录运行：

```bash
rg -n -S '月建冲爻|日辰冲爻|日月作用|合的层次|应爻' sources/六爻理法进阶_OCR纯文本.txt
rg -n -S '六神|综合取象|长生十二宫' sources/六爻象法进阶上_OCR纯文本.txt
rg -n -S '三刑|伏神|旬空|反吟|进退|隔山化爻|六害|八宫卦象' sources/六爻象法进阶下_OCR纯文本.txt
```

Windows PowerShell 也可以使用相同的 `rg` 命令。若当前环境没有 `rg`，应使用可用的只读文本检索工具，并保持相同的“按主题选择文件、读取局部上下文”原则。

## OCR 使用警告

OCR 可能有错字、断句问题，也可能误识干支、六亲、符号或专门术语。原文命中是资料线索，不是已经核对的盘面事实；遇到歧义时应记录“待确认”，并与原图、用户转录、排盘字段和统一流派口径交叉核对。

同一术语可能存在不同流派的解释。不要因为原文出现某个关系、六神或卦象，就把它当作唯一规则或单项吉凶开关；应说明采用的口径，并保留与其他证据的冲突。

## 引用与隐私

引用原始资料时只保留当前判断所需的最小上下文，注明来源文件和检索词，不把与问题无关的整段 OCR 复制到回答、示例或 Issue。盘面截图、姓名、账号、联系方式、出生资料等私人信息仍须先脱敏；公开仓库中的原始资料不应成为写入私人信息的理由。

若用户要求“按某本资料解释”，优先在对应文件中检索并说明“以下依据来自仓库中的 OCR 原文，可能存在识别误差”。若检索没有命中、文件不可读或上下文不足，应如实说明，不能凭关键词补造原文或盘面字段。
